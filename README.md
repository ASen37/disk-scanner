# Disk Scanner

一个基于 Python 标准库与 tkinter 构建的 Windows 磁盘空间扫描工具。以树形结构展示目录占用，支持逐级展开、按大小分级着色、右键定位与删除，并通过「一次遍历 + 全量索引 + 多线程分块」把大规模目录的统计耗时压到秒级。

> 无第三方依赖，单文件实现，仅需系统自带的 tkinter。

## 特性

- **树形浏览**：单击目录展开/收起，子项按占用大小降序排列，大头一眼可见。
- **分级着色**：目录按体量着色（≤100 MB 蓝、100 MB+ 金、512 MB+ 橙、1 GB+ 红）并加粗，文件保持黑色。
- **一次遍历扫描**：统计一个目录时顺带算出整棵子树里每个目录的大小，之后再展开子目录直接查索引，零磁盘操作。
- **多线程分块**：子目录较多时自动切块并行，充分利用磁盘并发读能力。
- **增量缓存**：结果写入 `cache.json`，下次启动按目录 mtime 校验复用，冷启动接近秒开。
- **重解析点安全**：符号链接与 junction 一律不进入统计，避免重复计数与环形嵌套导致的无限递归。
- **右键操作**：复制完整路径、在资源管理器中定位、跳转链接目标、删除（二次确认 + 安全保护）、清除缓存。
- **命令行模式**：`--list` 直接输出目录占用排行，便于脚本化与自测。

## 环境要求

- Windows 10 / 11
- Python 3.9 及以上（已在 3.14 上验证），需包含 tkinter 组件（python.org 官方安装包默认自带）

## 快速开始

```bash
git clone https://github.com/ASen37/disk-scanner.git
cd disk-scanner

# 图形界面，默认扫描 C 盘
python disk_scan.py

# 指定起始目录
python disk_scan.py D:\

# 命令行模式，不弹窗
python disk_scan.py --list C:\Windows
```

也可以直接双击 `start.bat`，按提示选择图形界面（`pythonw` 后台运行、无控制台窗口）或命令行扫描。

## 使用说明

- **切换磁盘**：顶栏下拉框选择盘符，立即重新扫描。
- **展开目录**：单击目录行或左侧箭头；已扫描过的目录会直接展示结果。
- **重新扫描**：选中目录后点击「重新扫描当前目录」，将忽略索引与缓存强制统计。
- **右键菜单**：复制路径、打开所在位置、删除、清除该目录及其子目录的缓存。
- **删除保护**：根目录不可删除；C 盘内容一律禁止删除；删除为永久删除（不进回收站），执行前有二次确认。
- **软链接 / junction**：在树中以绿色显示，不参与大小统计，可通过右键「跳转到链接目标位置」查看真实目标。

## 实现原理

### 1. 一次遍历 + 全量索引

`scan_once(root)` 使用显式栈（而非递归）遍历整棵子树，返回 `{目录路径: 字节数}`。统计某个目录的同时，其所有子孙目录的大小一并算出并写入索引。

这一点是性能关键：逐层展开时若每层都重扫子树，总成本是 O(深度 × 文件数)；一次遍历后整棵树只枚举一遍，展开任意已扫描目录均可直接查表。实测完整展开 `C:\Program Files`（6,247 个目录）由 13.4s 降至 1.3s。

### 2. 分块并行

子目录数量达到阈值（32）时，按块切分后交给固定大小的线程池并行处理，避免为数千个子目录创建数千个任务而引发 GIL 争用。线程数为 `min(32, CPU 逻辑核数 × 2)`，在 I/O 密集场景下能较好地压满磁盘队列。

### 3. 重解析点判定

Windows 的 junction（目录联接）在 Python 中 `DirEntry.is_symlink()` 返回 `False`，但 `st_file_attributes` 含 `FILE_ATTRIBUTE_REPARSE_POINT`（0x400）。pnpm 等包管理器大量使用 junction 互相指向，若仅依赖 `is_symlink()` 判断，会进入无限嵌套目录直至栈耗尽。

因此项目统一按属性位判定并跳过，这是扫描 `node_modules` 之类目录能否正常结束的关键。

### 4. 缓存与失效

- 缓存文件位于脚本同目录，结构为 `{"version": 2, "dirs": {路径: 字节}, "stamps": {路径: mtime}}`。
- 加载时校验目录 mtime，未变化则复用缓存值；旧版（v1）缓存会自动迁移。
- 缓存条目上限 400,000，超出后不再写盘，避免生成过大的 JSON 文件。

### 5. 界面消息限流

后台线程通过队列把结果送回 UI 线程，UI 每 120ms 轮询一次，单轮最多处理 2,000 条消息，避免超大目录一次性刷新导致界面卡顿。

## 性能实测

测试环境：16 逻辑核，NTFS 本地磁盘。

| 目录 | 规模 | 首次扫描 | 热缓存 |
|---|---|---|---|
| `C:\Program Files`（完整展开） | 6,247 个目录 / 15.0 GB | 1.30 s | 0.02 s（索引查表） |
| `C:\Windows\WinSxS` | 151,075 个目录 / 12.4 GB | 27–48 s | — |
| `F:\deepseek-harness`（含 node_modules） | 108,782 个文件 / 16,505 个目录 / 2.3 GB | 1.96 s | 0.94 s |

`WinSxS` 这类体量的目录受 NTFS 元数据随机读限制，增加线程到 32 以上收益已不明显；若需进一步提速，需直接读取 NTFS `$MFT`（需管理员权限，本项目未实现）。

## 已知限制

- 统计的是**逻辑大小**（文件字节数之和），与资源管理器「占用空间」（按簇对齐）存在差异。
- 硬链接文件会被重复计入，未做去重。
- 单目录超过 500 个子项时，界面仅展示前 500 个（大小仍按全量统计）。
- 无管理员权限无法读取部分系统目录，此类目录会被跳过计 0。
- 仅支持 Windows。
